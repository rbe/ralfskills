# Requirements of develop

The rows that the skill `r-develop` owns. `collection.md` says what the status means.

| Id | Title | Status | Statement |
| --- | --- | --- | --- |
| <a id="r-59"></a>R-59 | A slice that starts at develop | in force | A request that names a source file, a failing test, or a defect row of the roadmap starts at `r-develop`. A fix is such a request. When no history file exists for the task, `r-develop` creates the branch of the slice and asks `r-record` for a history id. `r-record` writes the file from its template and sets `roadmap:` to the roadmap row of the task, as [R-67](record.md#r-67) says. The Plan section is then one sentence that says why `r-plan` was not invoked. The slice then goes through `r-review` and `r-release` as every slice does. This applies to both. `r-develop` owns the request. `r-record` owns the file. |
| <a id="r-54"></a>R-54 | Stages read the accepted ADRs | in force | `r-develop` runs `make toon` and reads `docs/adr/index.toon` before it edits. It opens each ADR whose status is `Accepted` and whose `skills` names a skill this slice uses. `r-develop` stops when the change would break an accepted ADR. `r-review` opens the same ADRs. A change that breaks an accepted ADR is a finding. A repository that keeps `docs/requirements/` and no `docs/adr/` reads `docs/requirements-index.toon` in these steps, as the general rules say, and runs `make req ID=<ids>` for each row whose title or file names a part that the change touches. `r-develop` stops when the change would break such a row, and `r-review` writes a finding. This applies to a product repository. `r-develop` and `r-review` own the read. |
| <a id="r-47"></a>R-47 | Method, name, and test hygiene | in force | A method does one thing, or it only composes other methods. `r-develop` stops when a method does both. A unit, a function, a method, a class, and a file take their names from the domain. `r-develop` stops when a name is not from the domain. A behaviour change has a unit test. `make test` runs the unit tests. `make integration` is the one integration entry. `r-develop` stops when one target runs both. There is no skipped test, no silent catch, and no secret or personal data in a fixture. `r-develop` stops when one of these is present. `r-review` treats three misses as one check: a method that neither does one thing nor only composes other methods, a name that is not from the domain, and code that ignores the pattern `r-plan` named. A skipped test, a silent catch, or a secret or personal data in a fixture is a finding. This applies to both. `r-develop` owns the stops. `r-review` owns the one check. `r-plan` still chooses the pattern, as [R-7](plan.md#r-7) says. |
| <a id="r-8"></a>R-8 | Lint and test before done | in force | `r-develop` is not done until `make lint` and `make test` have passed. The linter is the one the language skill names, as [R-9](project-setup.md#r-9) says. Stop when either target fails. CI runs these same Make targets. Stop when lint, test, or coverage runs outside Make. This applies to both. `r-develop` owns the gate. `r-review` runs the same two targets and does not weaken a test to make the change pass. |
| <a id="r-34"></a>R-34 | Installed languages are the stack | in force | The language skills are `r-node`, `r-python`, `r-shell`, `r-jvm`, and `r-go`. The installed skill list is the stack. `r-develop` stops before it introduces a language that is not installed. It does not keep a hard-coded language list. It runs `make toon`, reads `docs/skill-index.toon`, and invokes each `language` row whose `files` or `names` match the files in hand. A file set with no matching row stops the step. A row is installed because the index lists only installed skills. Two languages means two disjoint file sets. Finish one set before editing the other. The line that names a language skill goes under Develop, as [R-20](record.md#r-20) says. This applies to both. `r-develop` owns the dispatch. Each language skill owns its files. |
