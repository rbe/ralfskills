# Requirements of migrate-docs

The rows that the skill `migrate-docs` owns. `collection.md` says what the status means.

| Id | Title | Status | Statement |
| --- | --- | --- | --- |
| <a id="r-5"></a>R-5 | Only migrate-docs reads the old board | in force | `migrate-docs` is the only skill that reads the content of the old board. `onboard` and `make old-board` only test whether its paths exist. `github-pipeline` does not require `BUGS.md`, `WAVES.md`, `FEATURES.md`, or `AGENTS.md`, and [R-46](github-pipeline.md#r-46) says it names none of the first three. This applies to both. `migrate-docs` owns the read. `github-pipeline` owns the delivery text. |
| <a id="r-29"></a>R-29 | migrate-docs scope | in force | `migrate-docs` runs when one of the old paths in [R-21](project-setup.md#r-21) exists, when `docs/ROADMAP.md` has the old line form, or when `AGENTS.md` exists. If none of them exists, it stops. It reads the old board, moves each still-true fact once, and deletes those paths in the same change. An open bug, an open audit finding, and a row of `docs/KNOWN_ISSUES.md` become roadmap rows of the kind defect. An Open row of `docs/DECISIONS.md` becomes a roadmap row of the kind question when it waits for an answer, and of the kind feature otherwise. Work already in progress becomes a roadmap row of the kind feature, and each line of an old `docs/ROADMAP.md` becomes such a row. A feature or wave that is a plan for later becomes a roadmap row with a proposal in `docs/proposals/`. A Decided row goes where `record` decides, as [R-53](record.md#r-53) says, and the skill asks the user where no home fits. An architecture or development rule goes to `docs/adr/`, with `adrs:` and `skills:`. A fixed bug, a shipped feature, or a wave narrative is not copied. A sentence of it that is still a rule follows the same choice rule. Where `AGENTS.md` exists, the skill folds a constraint that is still true into `CLAUDE.md` and then deletes `AGENTS.md`. It does not read skills or other documents. `record` issues every new id with `make id`, and gives each kind of old label that was used as an id a counter with `make id-raise` at the highest number used. The new row or file names the old label in its text. A test that names an old label names the new id instead. In a project whose Makefile has no include yet, the id check is `make -f .claude/skills/record/index.mk ids`. The skill does not leave the old files beside the new board, and `make old-board-delete` deletes the eight paths and then runs `make old-board`. This applies to a product repository that still has the old board. `migrate-docs` owns the move. |
