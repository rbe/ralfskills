# Requirements of node

The rows that the skill `r-node` owns. `collection.md` says what the status means.

| Id | Title | Status | Statement |
| --- | --- | --- | --- |
| <a id="r-36"></a>R-36 | Node and TypeScript | in force | `r-node` applies the Node rules when it is installed and the files are JavaScript or TypeScript. The package manager runs only through Make targets, never in a workflow step. This applies to a product repository that installs `r-node`, and `r-node` owns these rules. |
| <a id="r-147"></a>R-147 | Order of a major upgrade | in force | `r-node` gives the order of a major upgrade in `references/upgrade.md`. The order is Node, TypeScript, ESLint with its plugins, Vite with its React plugin, React, server libraries, and other runtime libraries. Each group ends with green gates. Other runtime libraries get one major version in each slice. The reason is that a fault then has one cause. This applies to a product repository that installs `r-node`, and `r-node` owns this rule. |
| <a id="r-148"></a>R-148 | Risks of a major upgrade | in force | `r-node` lists in `references/upgrade.md` what to check for each group of a major upgrade. The reason is that the known breaking changes of an area are read before the upgrade and not found by a failing gate. This applies to a product repository that installs `r-node`, and `r-node` owns this rule. |
| <a id="r-149"></a>R-149 | Files of a Node major change | in force | A change of the Node major version changes seven places in one slice. They are `.nvmrc`, `engines.node`, `NODE_VERSION` in the Makefile, the Containerfile default, the CI workflow, the bundler target, and `@types/node`. The reason is that one place left behind runs the project on two majors. This applies to a product repository that installs `r-node`, and `r-node` owns this rule. |
| <a id="r-150"></a>R-150 | Checklist for a new package | in force | Before `r-node` adds a package, it checks `package.json` for an overlap, a clear licence, and maintenance. It applies `r-security` and `r-performance` for a risky area. It runs the audit after the add. The reason is that each package is code that nobody reviewed. This applies to a product repository that installs `r-node`, and `r-node` owns this rule. |
| <a id="r-151"></a>R-151 | Vitest facts | in force | `r-node` states three Vitest facts in `references/coverage.md`. An agent run hides the console output of passing tests until `--reporter=default`. A client test sets an environment variable with `vi.stubEnv` and restores it with `vi.unstubAllEnvs`. A test that reads CSS runs under Node, because jsdom replaces each stylesheet with an empty string. This applies to a product repository that installs `r-node`, and `r-node` owns this rule. |
