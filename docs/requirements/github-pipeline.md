# Requirements of github-pipeline

The rows that the skill `github-pipeline` owns. `collection.md` says what the status means.

| <a id="r-42"></a>R-42 | What a shipment contains | in force | A shipment is a binary, a container image, or a library package, as [R-57](release.md#r-57) says. The image copies named files, not the work tree. `github-pipeline` has the four Containerfile templates `Containerfile.node`, `Containerfile.gradle`, `Containerfile.python`, and `Containerfile.go`, and the templates `containerignore` and `gitignore`. `.containerignore` keeps out `.git`, `.github`, `.claude/`, `apm_modules/`, `CLAUDE.md`, `docs/`, `build/`, `node_modules`, `data/`, `.env`, `.env.*`, and `*.tar`. Example data ships only from `examples/` when the path and the name say it is an example. Skills, the entry file, and development files stay out. `.claude/skills/` is committed so Make can include it, and the image still excludes `.claude/`. `.gitignore` keeps build output, image tars, `data/`, and `.env` out of git. A Make-only repository that ships a binary follows the same limit. This applies to a product repository. `github-pipeline` owns the image rules. `project-setup` points at them and states the limit for a binary. The other skills point at `project-setup`. |
| <a id="r-46"></a>R-46 | GitHub delivery contract | in force | `github-pipeline` is the delivery contract for a repository that publishes through GitHub. No file of `github-pipeline` names `BUGS.md`, `WAVES.md`, or `FEATURES.md`. A Make-only repository does not install this skill, as [R-45](project-setup.md#r-45) says. The files it checks are `docs/pipeline-rules.md`, `Containerfile`, `.containerignore`, `.gitignore`, and `Makefile`. Setup mode writes only what is missing or off the contract. Report mode writes no project file and does not run a publish target or a cleanup target. Setup mode names a second workflow file and does not delete it. There is one workflow, `.github/workflows/ci.yml`, named `CI`. `setup` runs first, then `build`, `test`, and `docs` beside each other, then `publish-container` and, when the project releases a JAR, `publish-github`, then `report`. `docs` is absent when there is nothing to render. `publish-*` runs on a push to the default branch or when `workflow_dispatch` selects that job, and it needs `build` and `test` to have succeeded. There is no `pull_request` trigger and no tag trigger. After tagging `vX.Y.Z`, start the publish job from the Actions tab. `report` is last and uses `if: ${{ !cancelled() }}`. In-progress runs are cancelled only when the push is not the default branch. Permissions are `contents: read` at the top, `actions: write` on `setup`, `packages: write` on `publish-container`, and `contents: write` on `publish-github`. A step is `actions/checkout`, an artifact upload or download, or `run: make <target>`. The runner label is `ubuntu-26.04`. `make version` prints `MAJOR.MINOR.PATCH-<run>` from the nearest strict `vMAJOR.MINOR.PATCH` tag plus `GITHUB_RUN_NUMBER`. It fails when that tag is missing, a nearer pre-release tag is closer, or the run number is missing. [R-57](release.md#r-57) says who creates the `v*` tag. `publish-tags` adds `latest` only on the default branch or when `GITHUB_REF` is unset. There is no `edge` tag, no `sha` tag, and no bare version tag. On the default branch, cleanup keeps that run and the next-lower run number on the same line, does not delete a version that still wears `latest` or any tag other than `MAJOR.MINOR.PATCH-<run>`, and deletes nothing off the default branch. A missing package is an empty list. `KEEP_VERSIONS` defaults to 2. `cleanup-github-releases` never deletes a name that is not `MAJOR.MINOR.PATCH-<run>`. Every upload sets `retention-days`: 1 for intermediates, 14 for `report` and rendered docs. `cleanup-actions-artifacts` deletes this repository's artifacts older than one hour, except `report`, `docs`, and the current run. `DRY_RUN=1` prints the deletions and deletes nothing. The test job runs `make editorconfig`, `make format`, `make lint`, `make test`, `make integration`, and `make coverage`. `make report` writes `build/report/index.md`. `docs/pipeline-rules.md` is copied from the skill template when it is missing. An existing "This repository" section and "Divergences" section stay as written. A divergence is the rule, what differs, and why. Allowed divergences are a JAR or binary `publish-github`, no `docs` job, no `publish-container` for a library, Gradle building the image from the tested JAR, and laptop targets no job calls. A second name for the same target, logic in the YAML, Docker, an upload without `retention-days`, publishing on a tag push or from a branch, a publish that skips `test`, and a version that does not come from `version` are not divergences. The contract test fails when the workflow, the include, retention, or a `run` step leaves this contract. Do not weaken that test. Node 24 belongs to the Node template only. A Gradle project uses the JDK in its template. No shell script is shipped. `sdlc.mk` holds `version`, `publish-tags`, the cleanups, `report`, `help`, `ci`, `ci-status`, `pull-request`, and `pull-request-merge`. `make ci-status` prints the result of the CI run for `HEAD`, or for `SHA=<sha>`, and exits non-zero when the run failed, did not finish, or does not exist. `WAIT=1` waits for the end. `make pull-request` opens a pull request from the current branch to `DEFAULT_BRANCH`, and `make pull-request-merge` merges it when its checks passed. All three run the GitHub CLI in the `gh-image` container, with the repository from `OWNER` and `NAME`, because that image has no Git. `ci-status` passes `-R owner/name`. `pull-request` and `pull-request-merge` call `gh api` with REST routes. All three stop with a message when neither `GH_TOKEN` nor `GITHUB_TOKEN` is set. The project sets `IMAGE`, `PACKAGE`, and `KEEP_VERSIONS` before the include, and may set `SDLC_JOBS`, `SDLC_CI`, and `SDLC_KEEP_ARTIFACTS`. `ci` runs `SDLC_CI` in order and does not publish. `$(call SDLC_LOG,job,_job)` writes the log of a publish job to `build/logs` and a failed summary when the job fails. The contract targets write no log. The command variables of the Node and Gradle templates write their summary to `build/summaries`. A recipe that must not run under `make -n` calls `$(THIS_MAKE)`. `make version PRINT=tag` prints the tag. The `setup` job runs `make cleanup-actions-artifacts` first. The publish job runs `make login`, then `make publish-container`, then `make cleanup-container-versions`. `publish-container` writes the version to `build/publish-version.txt`. Each job uploads `report-<job>` with `build/logs` and `build/summaries`. The workflow `env` holds `IMAGE` and `SDLC_DEFAULT_BRANCH`. This applies to a product repository that installs the skill. `github-pipeline` owns the contract. `release` invokes it as [R-22](plan.md#r-22) says. |
