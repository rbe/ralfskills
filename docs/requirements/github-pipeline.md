# Requirements of r-github-pipeline

The rows that the skill `r-github-pipeline` owns. `collection.md` says what the status means.

| Id | Title | Status | Statement |
| --- | --- | --- | --- |
| <a id="r-42"></a>R-42 | What a shipment contains | in force | A shipment is a binary, a container image, or a library package, as [R-57](release.md#r-57) says. The image copies named files, not the work tree, so skills, the entry file, and development files stay out. `.gitignore` keeps build output, image tars, `data/`, and `.env` out of git. This applies to a product repository. `r-github-pipeline` owns the image rules, and `r-project-setup` states the limit for a binary. |
| <a id="r-46"></a>R-46 | GitHub delivery contract | in force | `r-github-pipeline` is the delivery contract for a repository that publishes through GitHub. Setup mode writes only what is missing or off the contract, and report mode writes no project file and runs no publish or cleanup target. The contract test fails when the workflow, the include, retention, or a `run` step leaves the contract, and nobody weakens that test. This applies to a product repository that installs the skill, and `r-github-pipeline` owns the contract. |
| <a id="r-93"></a>R-93 | Workflow and jobs | in force | One pipeline workflow, `.github/workflows/ci.yml`, calls Make targets and nothing else. The jobs run in the order setup, then build and test, then publish, then report, and `report` always runs last. Each upload sets `retention-days`, so artifacts do not fill the quota. This applies to a product repository that installs the skill. |
| <a id="r-94"></a>R-94 | Triggers and permissions | in force | A `publish-*` job runs only when `workflow_dispatch` selects it, or on a push to the default branch when `AUTO_PUBLISH` is `true`. It needs `build` and `test` to succeed. `ci.yml` has no `pull_request` trigger and no tag trigger. Each job gets the least permission that it needs. This applies to a product repository that installs the skill. |
| <a id="r-95"></a>R-95 | Version and image tags | in force | `make version` prints `MAJOR.MINOR.PATCH-<run>` from the nearest strict `vMAJOR.MINOR.PATCH` tag and the run number. It fails when either is missing or a nearer pre-release tag exists. `publish-tags` adds `latest` only on the default branch. [R-57](release.md#r-57) says who creates the tag. This applies to a product repository that installs the skill. |
| <a id="r-96"></a>R-96 | Cleanup targets | in force | On the default branch, cleanup keeps the published version and the next-lower run on the same line. It never deletes a version that wears `latest` or a tag other than `MAJOR.MINOR.PATCH-<run>`. Off the default branch, CI deletes nothing, and `DRY_RUN=1` prints the deletions and deletes nothing. A missing package is an empty list. This applies to a product repository that installs the skill. |
| <a id="r-97"></a>R-97 | Divergences from the pipeline rules | in force | `docs/pipeline-rules.md` records the divergences of a project from the pipeline rules, and it repeats no rule. A divergence is the rule, what differs, and why. Logic in the YAML, Docker, a publish on a tag push, and a publish that skips `test` are never divergences. This applies to a product repository that installs the skill. |
| <a id="r-98"></a>R-98 | Targets and variables of sdlc.mk | in force | `sdlc.mk` holds the delivery targets of the pipeline, and the project sets `IMAGE`, `PACKAGE`, and `KEEP_VERSIONS` before the include. `make ci` runs the jobs in order and publishes nothing. A recipe that must not run under `make -n` calls `$(THIS_MAKE)`. This applies to a product repository that installs the skill. |
| <a id="r-99"></a>R-99 | CI status and pull request targets | in force | `make ci-status` prints the CI result for `HEAD` and exits non-zero when the run failed, did not finish, or does not exist. `make pull-request` and `make pull-request-merge` open a pull request and merge it when its checks passed. All three run the GitHub CLI in the `gh-image` container, so the host needs no `gh`, and they stop when no token is set. This applies to a product repository that installs the skill. |
| <a id="r-115"></a>R-115 | Host ports above 1024 | in force | A container may use a standard port inside, such as 443. A host binding of a published port uses a port above 1024, so no root privileges are needed. No template of a skill publishes a lower host port. This applies to a product repository that installs the skill, and `r-github-pipeline` owns this rule. |
| <a id="r-117"></a>R-117 | Publish the client package | in force | A project with `client/package.json` has the workflow `.github/workflows/publish-client.yml`, copied from the template. It runs on `workflow_dispatch` or on a tag `client-v*`, and it invents no version: the version is that of `client/package.json`. A second run of the same version creates no second release and no second package version. This applies to a product repository that installs the skill, and `r-github-pipeline` owns this rule. |
| <a id="r-119"></a>R-119 | Smoke check of a web image | in force | The smoke check of a web image starts the image and checks that the API path returns the expected body. It also checks that the page at `/` holds the root element of a single-page app. A failed check fails `make build`. This applies to a product repository that installs the skill, and `r-github-pipeline` owns this rule. |
| <a id="r-120"></a>R-120 | Check a tag before it is pushed | in force | `make check-tag TAG=vX.Y.Z` runs before the owner pushes a `v*` tag and writes nothing. It exits non-zero when `make version` would not accept the tag or when `HEAD` is not the tip of the default branch. `r-release` creates no tag, as [R-57](release.md#r-57) says. This applies to a product repository that installs the skill, and `r-github-pipeline` owns this rule. |
| <a id="r-121"></a>R-121 | Only a human publishes a large artifact by default | in force | By default only a human publishes a large artifact, such as a container image or a JAR release, to a registry, with `workflow_dispatch`. The reason is the GitHub quota of storage, artifacts, and minutes. A project opts in to a publish on every push to the default branch with the repository variable `AUTO_PUBLISH` set to `true`. This applies to a product repository that installs the skill, and `r-github-pipeline` owns this rule. |
| <a id="r-123"></a>R-123 | No CI run for a push of board files only | in force | A push that changes only board files runs no build, test, or publish, because the CI run of the commit before it already passed. `make ci-scope` decides this, and any other file, any doubt about the base commit, and any other event run the full jobs. A skipped job counts as passed, so the close still merges. This applies to a product repository that installs the skill, and `r-github-pipeline` owns this rule. |
