# Requirements of jvm

The rows that the skill `r-jvm` owns. `collection.md` says what the status means.

| Id | Title | Status | Statement |
| --- | --- | --- | --- |
| <a id="r-39"></a>R-39 | JVM languages | in force | `r-jvm` applies when it is installed and the files are Java, Groovy, Grails, or Gradle. Its `files` are `java`, `groovy`, `gradle`, and `kts`. Read the reference that matches the file: `references/java.md`, `references/groovy.md`, `references/grails.md`, or `references/gradle.md`. `make test` runs the tests. `make build` runs Gradle. The workflow does not call Gradle itself. Java prefers a record for an immutable value. A domain type does not depend on the entry point that calls it. Use constructor injection rather than static state. A test name says the expected result and the condition. One assertion concept per test. Java's formatter is google-java-format and its linter is Checkstyle. Groovy is the language of a Grails application and of a script a build may run. A workflow step does not call a Groovy script. The Make target does. Groovy's linter is CodeNarc. Grails is one application. Management commands stay in the command the project already uses, and that command runs from `make`. Do not add a second configuration channel beside the one the application already reads. The Gradle wrapper is the Gradle the project runs. Versions live in the version catalog. `make format` runs google-java-format through Spotless (`spotlessCheck`). `make lint` runs Checkstyle (`checkstyleMain`). `make coverage` runs JaCoCo's XML through diff-cover. Podman, XDG paths, and shipment contents stay in `r-project-setup`. This applies to a product repository that installs `r-jvm`. `r-jvm` owns these rules. |
| <a id="r-116"></a>R-116 | Gradle in Podman reaches Podman | in force | Gradle runs in a container, so the host needs no Java toolchain. A Gradle task that starts containers, such as a Testcontainers test, runs through `$(GRADLE_PODMAN)`. It is `$(GRADLE)` with the Podman socket of the host mounted at `/run/podman/podman.sock`, `CONTAINER_HOST` set to that socket, and the host network. `make podman-socket` starts the socket when it is off. `templates/Makefile.gradle` of `r-jvm` and of `r-github-pipeline` both define `PODMAN_SOCKET`, `GRADLE_PODMAN`, and `podman-socket`. The image of that run holds a Podman client. This applies to a product repository that installs `r-jvm`. `r-jvm` owns this rule. |
