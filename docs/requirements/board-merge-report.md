# Requirements of board-merge-report

The rows that the skill `board-merge-report` owns. `collection.md` says what the status means.

| Id | Title | Status | Statement |
| --- | --- | --- | --- |
| <a id="r-77"></a>R-77 | Board merge report | in force | `board-merge-report` reads the requirement rows in force, the ADRs in `docs/adr/`, and the files in `docs/history/`, and it writes nothing. A planned row, a roadmap row, and a proposal are out of scope. It reports six kinds of finding. A merge joins rows that state the same obligation. A shorten keeps the rows and drops the sentences that another row states. A cover shrinks a row to its intent and its reason when a test with the line `id:` pins every other fact of the row. A history deletion removes a closed history file, and a file that holds the only copy of a reason is flagged, so that the reason moves to a row first. A history file is never merged. Before a finding enters the report, the skill tries to refute it. Another actor, another repository kind, or another stage means no merge. A contradiction is two rows or files that state opposite or unequal facts about one thing, and an against-code finding is a row that the code does not do, does differently, or names something that does not exist. For both, the skill reads the code of the collection: `skills/*/SKILL.md` and references, the makefiles, templates, scripts, `Makefile`, `CLAUDE.md`, and `README.md`. If the code decides, the finding names the false row, the evidence as path and line, and the corrected sentence. If the code does not decide, or the row may be right and the code wrong, the finding is a question to the owner with the choices, and the fix is a task for `develop`. The numbers come from `make board-numbers`, not from the agent. For each unit the target prints the id, the kind, the status, the words, the tests that name the id with `id:`, the links to the id from other documents, and the frontmatter lists that name it. A frontmatter list of a history file counts, because it names an id that the slice wrote or proved. A link in the text of a history file does not count, because the text keeps the ids that were deleted later. `IDS=` narrows the output. The report has one table for each kind, and its last lines say how to choose by id: `merge R-51 R-76`, `shorten R-12`, `cover R-40`, `delete H-2026-11-15-slug`, `fix R-12`. The id that survives a merge is the one that more tests name. `merge-report.mk` beside the skill owns the target, and `project.mk` and `sdlc.mk` include it. This applies to this collection and to a product repository. |
| <a id="r-86"></a>R-86 | Size limit and test names of the cover finding | planned | The kind `cover` names no size limit, so a row with one unpinned fact still counts. `make board-numbers` prints the count of tests, not their names. Decide the least saving that a cover finding reports, and whether `make board-numbers` prints the test names of an id. |
