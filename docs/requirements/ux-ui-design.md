# Requirements of r-ux-ui-design

The rows that the skill `r-ux-ui-design` owns. `collection.md` says what the status means.

| Id | Title | Status | Statement |
| --- | --- | --- | --- |
| <a id="r-33"></a>R-33 | Interaction questions | in force | `r-ux-ui-design` applies when the change has a screen, a control, or a visual. It covers interaction only, because tokens, the type scale, and the component catalogue are product catalogues, as [R-52](collection.md#r-52) says. `r-plan` asks what the person does and what each state shows, and `r-review` checks focus, contrast, labels, and that no state shows by colour alone. This applies to both, when the skill is installed, and `r-ux-ui-design` owns the questions. |
| <a id="r-138"></a>R-138 | UI languages are named | in force | `r-ux-ui-design` makes `r-plan` ask which UI languages `CLAUDE.md` names. It makes `r-review` check that `CLAUDE.md` names them. It also checks that each visible text is in one of them. The reason is that a text in an unnamed language has no owner. This applies to a product repository that installs `r-ux-ui-design`, and `r-ux-ui-design` owns this rule. |
| <a id="r-139"></a>R-139 | Date-only value is not parsed as Date | in force | `r-ux-ui-design` makes `r-review` check that a value with a date and no time is not parsed with the `Date` constructor. The reason is that the constructor reads it as midnight UTC, so the screen shows the previous day west of UTC. This applies to a product repository that installs `r-ux-ui-design`, and `r-ux-ui-design` owns this rule. |
| <a id="r-140"></a>R-140 | Visible text is not built from pieces | in force | `r-ux-ui-design` makes `r-review` check that code does not build a visible text from word pieces and that a plural follows the rule of the language. The reason is that word order and plural forms differ between languages. This applies to a product repository that installs `r-ux-ui-design`, and `r-ux-ui-design` owns this rule. |
| <a id="r-141"></a>R-141 | Decimal input is a text input | in force | `r-ux-ui-design` makes `r-review` check that a decimal input for a locale with a decimal comma is a text input with `inputmode="decimal"` and not `type="number"`. The reason is that a number input rejects or changes the comma in some browsers. This applies to a product repository that installs `r-ux-ui-design`, and `r-ux-ui-design` owns this rule. |
| <a id="r-142"></a>R-142 | Format tests pin the locale | in force | `r-ux-ui-design` makes `r-review` check that a test of a formatted date or number pins the locale. The reason is that the output of the test then does not depend on the machine. This applies to a product repository that installs `r-ux-ui-design`, and `r-ux-ui-design` owns this rule. |
