# Requirements of r-ux-ui-design

The rows that the skill `r-ux-ui-design` owns. `collection.md` says what the status means.

| Id | Title | Status | Statement |
| --- | --- | --- | --- |
| <a id="r-33"></a>R-33 | Interaction questions | in force | `r-ux-ui-design` applies when the change has a screen, a control, or a visual. It is interaction only. Tokens, the type scale, and the component catalogue are product catalogues, as [R-52](collection.md#r-52) says. `r-plan` asks five questions. What does the person do, in one sentence? What does the empty state show, and what does the error state show? Can a keyboard reach every control a pointer can reach? Which control returns focus to which control when a dialog closes? Which state does the screen show, and what shows it besides colour? `r-review` checks nine things. The screen matches the answers, including the empty state and the error state. Focus is visible. Text and controls meet contrast level AA of WCAG 2.2. Each input has a programmatic label. A validation error is text next to its field, not only a colour. No state shows by colour alone. A decorative icon is hidden from assistive technology, and an icon-only control has an accessible name. No content flashes more than three times in one second. A dialog returns focus to the control that opened it. A token that belongs to one product was not copied into this skill. This applies to both, when the skill is installed. `r-ux-ui-design` owns the questions. |
