# Requirements of r-api-design

The rows that the skill `r-api-design` owns. `collection.md` says what the status means.

| Id | Title | Status | Statement |
| --- | --- | --- | --- |
| <a id="r-10"></a>R-10 | API shape questions | in force | `r-api-design` covers HTTP and the public surface of a module or a library. The route catalogue is a product catalogue, as [R-52](collection.md#r-52) says. The skill asks what is exported, what stays internal, and what the resource, the verb, and the status on success are. When the slice changes a route, `r-plan` asks the resource, the verb, and the status on success, the status and the error body on failure, and which existing contract has to change in the same change as the handler. Otherwise the answer is `not HTTP`. When the slice changes what callers can import, `r-plan` asks what is exported, what a caller may rely on, and what stays internal. Otherwise the answer is `not a module`. `r-review` skips the HTTP checks when the answer was `not HTTP`, and skips the export checks when the answer was `not a module`. The route matches the answers, including the failure status and the error body. The contract and the handler changed together. A new failure mode has a status and a body. A success body is not an error shape. The export list matches the answers. A caller relies only on what the answers named. A name the answers called internal is not exported. This applies to both, when the skill is installed. `r-api-design` owns the questions. |
