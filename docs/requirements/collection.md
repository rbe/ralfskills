# Requirements of collection

Each row is a rule that holds or work to do. The status `in force` is a rule that this skill set fulfills. The status `planned` is open work, or an open question whose statement names the choices. A row states the intent and the reason of a rule. The skill text holds the details, and no row repeats them. A sentence that begins with `This applies to` says where the row holds: this collection, a product repository, or both. The rows stand in one file for each skill that owns them, in `docs/requirements/<skill>.md`. A row with no owning skill stands in this file. The index `docs/requirements-index.toon` lists the id, the title, the status, the file, and the owner of each row.

| Id | Title | Status | Statement |
| --- | --- | --- | --- |
| <a id="r-16"></a>R-16 | APM skill package | in force | ralfskills is an APM skill collection. Each skill is one directory `skills/r-<name>/SKILL.md`, and there is no root `SKILL.md`. A project commits `.claude/skills/`, `apm.yml`, and `apm.lock.yaml`, because its Makefile includes files from `.claude/skills/`. [R-60](project-setup.md#r-60) lists the skills. This applies to this collection, and APM is the installer. |
| <a id="r-17"></a>R-17 | Install path and agent-agnostic text | in force | Installed skills live under `.claude/skills/`. Skill text is agent-agnostic: a skill file names no AI coding tool, no tool folder, and no model. Only the Agents section of the `CLAUDE.md` template names models. This applies to this collection and to the skills a product repository installs. |
| <a id="r-18"></a>R-18 | CLAUDE.md is the entry file | in force | `CLAUDE.md` is the only entry file, and the repository has no `AGENTS.md`. The entry file names the parts that [R-60](project-setup.md#r-60) lists and imports the general rules with one line, as [R-76](project-setup.md#r-76) says. This applies to this collection and to a product repository that uses the skills. [R-29](migrate-docs.md#r-29) says how an old `AGENTS.md` goes. |
| <a id="r-52"></a>R-52 | Product skills stay in the product | in force | A product skill stays in the product repository and is named in its `CLAUDE.md`. A product catalogue, such as a route list, tokens, a type scale, or a component catalogue, stays there too. This collection ships no `.apm/agents` and no persona, because `r-record` here is a skill. This applies to this collection. A product repository owns its own extra skills. |
| <a id="r-19"></a>R-19 | Four numbered stages | in force | The stage skills are `r-plan`, `r-develop`, `r-review`, and `r-release`, in that order. Each has one `<steps>` block, a numbered list of its work, with a step that asks `r-record` to write its history section. The frame that every skill repeated before is in the general rules, as [R-76](project-setup.md#r-76) says. This applies to both, and each named skill owns its own list. |
| <a id="r-72"></a>R-72 | Update path and version tags | in force | A project takes a new version of this collection by setting `ref` to a `vMAJOR.MINOR.PATCH` tag and running the update steps that the README states. This collection tags its releases with such a tag, and [R-57](release.md#r-57) says who creates it. This applies to a product repository. The README owns the text. |
| <a id="r-100"></a>R-100 | Test of the collection in a test repository | in force | The owner tests the collection in a test repository before a version tag, with a branch of the collection that is not tagged yet. Never push to or change the default branch of the test repository. Never delete a release, a tag, or a package version for real, and work only on the two test branches. [R-72](#r-72) states the path to a tagged version. This applies to this collection. The README owns the steps. |
| <a id="r-101"></a>R-101 | Diagrams of the collection | in force | The README shows two diagrams as SVG files, `docs/diagrams/collection-map.svg` and `docs/diagrams/board-map.svg`. A change that alters what a diagram shows updates the diagram in the same commit. This applies to this collection. The README owns the text. |
| <a id="r-35"></a>R-35 | Stages stay technology-agnostic | in force | Stage skills stay technology-agnostic and redirect to the language skill, and framework detail stays in `references/` beside the language skill. A framework file replaces neither the language skill nor the stage skill. This applies to both. The language skill owns the pointer, and the product repository names a framework in `CLAUDE.md`. |
| <a id="r-66"></a>R-66 | Makefile templates of the language skills | in force | Each language skill has Makefile templates that fill every command variable of the Make contract. It also has one tooling target for a new project, such as `make node-tooling`. A second run of a tooling target changes nothing, and a file or dependency already in the project stays. This applies to a product repository. Each language skill owns its templates and its include file. |
| <a id="r-122"></a>R-122 | Include files of the language skills | in force | Each language skill has one include file with the Make targets of its language. A project includes it from the installed skill and keeps no copy, so the copies cannot drift, and a template defines none of those targets. The root `Makefile` of this collection is Python only and includes no language file. This applies to a product repository. Each language skill owns its file. |
| <a id="r-51"></a>R-51 | Communication contract | in force | The communication contract lives in `rules.md` of `r-project-setup`, which `CLAUDE.md` imports, because every agent reads that file in every session. It is written for a reader who reads each reply once, often after a break, and decides from it. No `SKILL.md` restates it. This applies to this collection and to a product repository, which gets the contract through the import line of the template, as [R-60](project-setup.md#r-60) says. |
| <a id="r-105"></a>R-105 | Skill names start with r- | in force | Each skill has a folder name and a `name` that start with `r-` and are equal. The prefix lets a project install skills of other collections without a name clash. A unit test checks the prefix and the equal name. This applies to this collection. |
| <a id="r-108"></a>R-108 | Plugin r for hooks, agents, and MCP servers | planned | The collection also ships a Claude Code plugin named `r`, built by `apm pack`. The plugin holds only hooks, agent files, and MCP servers, and no skill, because the Makefile includes and CI read skills in `.claude/skills/r-<name>/`. A project names the marketplace and the plugin in `.claude/settings.json` with `extraKnownMarketplaces` and `enabledPlugins`, pinned by `ref` and `sha`. The plugin also ships a hook that blocks a bare `git add` of the whole working copy, as [R-114](release.md#r-114) states for the agent. This applies to this collection and to a product repository. |
