# Each id in a document is a link

## Plan

The slice: each id in running text of a document under `docs/`, and each id in a generated document, is a link to its item.

Out of scope: an id in the frontmatter and in the id cell of a table. An id in a test file, a commit message, or a skill file.

Questions and answers:

1. Question: where must an id be a link? [R-27](../REQUIREMENTS.md#r-27) says that a document does not build a path to another document, and the scripts read the ids in table rows and in the frontmatter. Options: the generated documents only, the generated documents and the running text of the source documents, or every place. Recommended: the generated documents only. Answer of the owner: the generated documents and the running text of the source documents.

The result: `[D-9](../DECISIONS.md#d-9)` for a table row, and `[ADR-0001](../adr/ADR-0001.md)` for a file. The empty case: a document with no id is not changed. The error case: a retired id or an unknown id has no target and stays plain text.

Boundary: `record` owns the ids, so it owns the link tool and the two Make targets. `project-report` does not import code of `record`. It has its own small helper for the paths from `build/`.

Pattern: a tool writes the links. An agent writes the plain id and runs the target. The tool gives the same result when it runs a second time.

The choice replaces a part of [R-27](../REQUIREMENTS.md#r-27). [D-12](../DECISIONS.md#d-12) records it.

## Develop

`links.py` in `record` finds each id that a table row or a frontmatter block defines. `make links` gives each table row an anchor and writes a link for each id in running text. `make links-check` fails when a document would change. The four scripts that read a table id ignore the anchor. The decision log and the project report give each item an anchor and link each id.

A cheaper model wrote the scripts and the tests from a written design. The design, the review of the result, and the skill text are from the main session.

`make links` ran on this collection. `docs/REQUIREMENTS.md`, `docs/DECISIONS.md`, and the history files have their anchors and links. The retired ids in the older history files stay plain text.

[R-69](../REQUIREMENTS.md#r-69) is the new requirement. [R-27](../REQUIREMENTS.md#r-27) says where an id stays plain text.

Python and shell are the language skills.

## Review

Every gate passed through Make in Podman with the pinned default images: `make format`, `make lint`, `make test`, `make integration`, `make editorconfig`, `make coverage`, `make test-changed`, `make ids`, `make toon`, `make links-check`, `make project-report`, and `make decision-log`. A second `make links` changed no file.

security: the tool reads and writes files under `docs/` only. No listener, no secret, no command from a document.

privacy: no personal data.

ux-ui-design: the link text is the id, so the text reads as before.

api-design: not HTTP. Not a module export. The anchor of a row, the id in lowercase, is the interface between the documents.

Finding, fixed in this change: the tool removed a link that was an example in a code span. Location: `unlink` in `links.py`. Evidence: this history file lost its two example links at the first run. The check that proves the fix: the test `test_a_link_in_a_code_span_or_a_code_block_is_an_example_and_stays`.

Left alone: a decision that is a frontmatter block in `docs/DECISIONS.md` has no anchor. `record` defines a decision as a table row. The documents of `rbe/gh-sweep` get their links when that project updates the skills and runs `make links`.
